# Запросы SaveMoney

Импортируйте `SaveMoney.postman_collection.json` и
`Local.postman_environment.json` в Postman, выберите окружение **Local · SaveMoney**.
Базовый URL: `http://127.0.0.1:8000/api/v1`.

Запустите отдельный демонстрационный сервер:

```sh
python -m savemoney.server --storage memory --port 8000
```

Для проверки сохранения в MongoDB запустите `docker compose up -d mongo`, экспортируйте
`SAVEMONEY_MONGO_URI=mongodb://127.0.0.1:27018` и используйте отдельную базу:

```sh
python -m savemoney.server --storage mongo --database savemoney_postman --port 8000
```

Коллекция создаёт демонстрационные данные и сохраняет их на сервере. Каждый запуск
получает новые ID от API. Ноябрь 2026 должен оставаться открытым; закрытые периоды
повторный запуск не открывает. Для другого состояния используйте новую демонстрационную
БД или новый сервер в памяти.

## Collection Runner

Выберите папки **01 · Main workflow** и **02 · Rejected requests preserve state**,
оставьте порядок запросов и запустите одну итерацию. Повторный запуск также допустим.

- Папка 01: категории, доход 85 000 ₽, обязательство 50 000 ₽, расход 450 ₽,
  конверт 30 000 ₽, цель и накопление 750 ₽, фильтры, пагинация, настройки,
  удаление и восстановление операции. Проверки используют собственные сущности,
  поскольку общий баланс и резерв зависят от уже существующих данных.
- Папка 02: ошибки 400/404/405/415/422, `Allow`, строгие суммы и поля,
  повтор query-параметра, отклонённый импорт. Снимки до и после подтверждают,
  что ошибочные запросы не изменяют бюджет. Папку можно запускать отдельно.
- Папка 03: необязательный экспорт → импорт → повторный экспорт с проверкой
  всех ID и метаданных. По умолчанию каждый запрос этой папки пропускается.

ID и временные данные сохраняются в переменных коллекции автоматически. Денежные
суммы передаются целыми копейками. Тема настроек читается и записывается прежней,
чтобы проверка PATCH не меняла выбранную тему.

## Необязательный импорт

Импорт **полностью заменяет бюджет**, поэтому выполняйте папку 03 только на отдельной
демонстрационной БД без других клиентов. Установите `allowSnapshotImport=true`
в окружении, запустите папку целиком и затем верните `false`. Конкурентные изменения,
возникшие между экспортом и импортом, могут быть перезаписаны. Запроса сброса всего
бюджета в коллекции нет.

## Newman

Команда устанавливает только временный инструмент запуска; зависимости Python-проекта
не меняются:

```sh
bunx newman@6.2.3 run postman/SaveMoney.postman_collection.json \
  -e postman/Local.postman_environment.json --iteration-count 2 --bail
```

Без изменения окружения папка 03 будет пропущена. Для отдельного демонстрационного
сервера можно явно включить только проверку импорта:

```sh
bunx newman@6.2.3 run postman/SaveMoney.postman_collection.json \
  -e postman/Local.postman_environment.json \
  --folder '03 · OPTIONAL snapshot roundtrip' \
  --env-var allowSnapshotImport=true --bail
```

Для временного порта задайте `--env-var baseUrl=http://127.0.0.1:PORT/api/v1`.
