# Чек-поинт 3: сервер, MongoDB и документация

Учебный однопользовательский SaveMoney. Ветка результата — `stage-3`. Реализованы этапы 7–9: REST API,
HTTP-сервер без фреймворков, Postman, MongoDB/PyMongo и mongomock.
Интерфейсы React Native и Tauri остаются следующим этапом.

## Быстрый запуск

Нужны Python 3.13, Git и Docker с Compose. В корне репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
docker compose up -d
python -m savemoney.server --init
```

API: `http://127.0.0.1:8000/api/v1`. Swagger: `http://127.0.0.1:8000/swagger`.
Try it out → Execute выполняет настоящий запрос. Для загрузки Swagger нужен интернет
(CDN с закреплённой версией ресурсов). Остановка сервера: Ctrl+C.
Повторный запуск не очищает базу. `--init` создаёт «Прочее» и месячный период;
прошедшие месяцы переходят к разбору остатков. GET не создаёт данные.

```sh
curl http://127.0.0.1:8000/api/v1/categories
curl 'http://127.0.0.1:8000/api/v1/dashboard?date=2026-11-05'
```

Для временных данных: `python -m savemoney.server --storage memory --init`.
В этом режиме после остановки всё исчезает. Обычный запуск использует MongoDB.
При недоступной базе API возвращает 503; автоматической подмены базой в памяти нет.

## Настройки

| Параметр | Значение по умолчанию |
|---|---|
| `--storage` | `mongo` (`memory` только для временного запуска) |
| `--host` | `127.0.0.1`; допустим также `localhost` |
| `--port` | `8000` |
| `--database` / `SAVEMONEY_DATABASE` | `savemoney` |
| `SAVEMONEY_MONGO_URI` | `mongodb://127.0.0.1:27018` |
| `--date` | Текущая дата; используется командой `--init` |

`.env.example` показывает имена переменных; сервер не загружает `.env` автоматически.
Пример: `export SAVEMONEY_MONGO_URI=mongodb://127.0.0.1:27018`.
MongoDB опубликована Docker только на loopback, данные лежат в volume `mongo-data`.
`docker compose stop` останавливает базу, сохраняя данные.
`docker compose down -v` удаляет volume и все его данные — для обычной остановки не нужен.

## Сценарий пользователя

1. Создать категории дохода и расходов через POST `/categories`.
2. Создать источник дохода и обязательные платежи через `/income-sources`, `/obligations`.
3. Создать период POST `/periods` с `{"date":"2026-11-05"}`.
4. Назначить конверт PUT `/periods/{id}/envelopes/{categoryId}` с `limitAmount`.
5. Записывать доходы и расходы POST `/transactions`; суммы — целые копейки.
6. Проверять `/dashboard?date=...` и `/reports/categories?periodId=...`.
7. Создавать цели через `/goals`, движения накоплений через `/transactions`.
8. При следующем периоде разбирать остатки через `/periods/{id}/closures`:
   `burn`, `carry_over`, `to_goal`. Решение повторяемо без двойного перевода.

Удобнее пройти готовую [коллекцию Postman](postman/README.md): она связывает ID
между запросами и проверяет ответы. Пользовательского графического интерфейса пока нет.
Документация всех 38 операций и JSON-примеры находятся в README и openapi.json.

## Перенос данных из памяти в MongoDB

Сначала, пока сервер с данными в памяти ещё работает, выгрузить снимок:

```sh
curl --fail http://127.0.0.1:8000/api/v1/snapshots/current -o /tmp/savemoney-snapshot.json
```

Остановить временный сервер и импортировать снимок в отдельную базу MongoDB:

```sh
python -m savemoney.server --database savemoney_import --import-file /tmp/savemoney-snapshot.json
python -m savemoney.server --database savemoney_import
```

Импорт полностью заменяет выбранный бюджет. Для проверки используйте отдельную БД,
как в примере. Проверяются схема, ссылки, уникальность, финансовая история, остатки
и эффекты закрытия. При ошибке прежние данные остаются целыми. Лимит тела и импорта —
1 MiB. ID и метаданные сохраняются. Статусы целей active/completed вычисляются заново
на текущую дату; archived сохраняется. Экспорт содержит личные финансовые данные;
не добавляйте такие снимки в Git.

## Устройство сервера и базы

`server.py` разбирает HTTP; `application.py` выполняет 38 операций; `api_validation.py`
использует схемы из `openapi.json`; `api_codec.py` связывает JSON и доменные классы.
`Budget` и чистые расчёты отвечают за финансовые правила. `storage.py` сохраняет состояние.

MongoDB содержит один документ в коллекции `budgets`:

```json
{"_id":"budget","revision":1,"snapshot":{"schemaVersion":1,"categories":[]}}
```

Это сокращённая схема хранения: реальный снимок содержит все массивы и настройки.
Изменение готовится на копии и сохраняется только после проверки. Фильтр записи
содержит ожидаемую ревизию, поэтому конкурирующая запись получает 409 вместо потери
данных. Повторять POST автоматически после неопределённого сетевого сбоя нельзя.

Один документ позволяет атомарно импортировать бюджет и закрывать период без
многодокументных транзакций. Это осознанное ограничение учебной версии: весь бюджет
читается и проверяется в Python. Для больших объёмов потребуется разделение коллекций,
индексы, запросы на стороне базы и транзакции для связанных операций.

## Проверки и CI

```sh
SAVEMONEY_TEST_MONGO_URI=mongodb://127.0.0.1:27018 sh scripts/check.sh
```

Команда запускает Ruff, проверку форматирования, pytest, coverage с порогом 100%
и компиляцию Python. Без `SAVEMONEY_TEST_MONGO_URI` пропускается только тест отдельного
процесса с настоящей MongoDB; остальные проверки, включая mongomock, выполняются.
В GitHub Actions настроен сервис MongoDB и переменная для этого теста.

Реальная проверка создаёт отдельные временные БД, сохраняет операции через HTTP,
перезапускает процесс сервера и переносит экспорт через CLI. Удаляются только созданные
тестом базы. [Postman/Newman](postman/README.md) дополнительно проверяет сценарии API.

GitHub Actions исполняется после push/PR. До публикации текущей ветки результаты
локальных проверок не являются результатами удалённого CI.

## Демонстрация команды 10

Отдельная демонстрационная база — `savemoney_defense`, она не затрагивает основной бюджет.
Сервер для защиты запускается командой:

```sh
python -m savemoney.server --database savemoney_defense --port 8000
```

В текущем локальном комплекте есть синтетический снимок `docs/checkpoint3/demo-initial.json`.
Чтобы начать показ заново, импортируйте его **только в демонстрационную базу**:

```sh
python -m savemoney.server --database savemoney_defense --import-file docs/checkpoint3/demo-initial.json
```

После импорта уже запущенный сервер увидит новые данные при следующем запросе.
В Swagger: GET `/api/v1/dashboard` с date `2026-11-05` → available 3500000;
POST `/api/v1/transactions` с телом ниже → 201; повторный GET → available 3455000,
остаток конверта Еда 2955000. Значения в JSON — копейки.

```json
{"type":"expense","amount":45000,"date":"2026-11-05","categoryId":"demo-food","comment":"Обед"}
```

Каждый повтор POST добавляет новую трату. Для повторного показа сначала восстановите
только демонстрационную базу из указанного снимка. Рабочие данные не сбрасываются.
